# MV-CS060-10UC-PRO 相机接口测试

针对海康机器人 **MV-CS060-10UC-PRO**（6 MP / 3072×2048 / IMX178 / USB3 Vision）的接口测试工具，
按照《评判标准 v2.1-A（A 方案）》采集、计算并分别给出**接口综合判定**与**图像质量诊断**：
接口判定统计 B 组计入项（坏点率可选），FFT 与图像质量默认只诊断；另附一组**补充检查**（链路带宽、帧完整性、帧率偏差、最长帧间隔、长时稳定性、进程资源、暗场热像素），
输出控制台结论、Markdown 报告、JSON 数据、逐帧 CSV 和相机参数快照。

测试在 **NUC** 上运行（Windows 或 Ubuntu 均可），依赖海康 MVS 客户端的 Python SDK。

> A 方案：接口判定只统计计入项；FFT 峰值比与图像质量项默认只作诊断，`--image-quality enforce` 可把坏点率计入。

## 2. 环境准备

### 2.1 安装 MVS 客户端（必须）

* 下载海康机器人 MVS（Windows / Linux 安装包），安装后自带 Python SDK：
  * Windows：`C:\Program Files (x86)\MVS\Development\Samples\Python\MvImport`
  * Linux：`/opt/MVS/Samples/64/Python/MvImport`
* 先用 MVS 客户端确认能正常预览相机，再跑本工具。

### 2.2 Python 依赖

```bash
python -m pip install -r requirements.txt   # 仅需 numpy
```

### 2.3 Linux（Ubuntu NUC）补充

```bash
export MVCAM_COMMON_RUNENV=/opt/MVS            # 写入 ~/.bashrc

sudo cp /opt/MVS/Driver/udev/99-mvusb.rules /etc/udev/rules.d/ 2>/dev/null || true
sudo udevadm control --reload-rules && sudo udevadm trigger

sudo cpupower frequency-set -g performance     # 降低时间戳抖动
```

## 3. 快速开始

```bash
# 默认：真实相机，采集 60 s（接口判定 + 图像诊断 + 补充检查）
python run_test.py

# 平场 + 暗场两段（结束后提示盖住镜头，再采 4 帧暗场）——推荐
python run_test.py --duration 180 --dark-field

# 只枚举设备
python run_test.py --list

# 只测链路四项、跳过坏点/FFT
python run_test.py --quality-frames 0

# 没相机时验证流程
python run_test.py --simulate --duration 15
python run_test.py --simulate --dark-field --no-wait    # 连暗场检查一起演练
```

主要参数：

| 参数 | 说明 |
| --- | --- |
| `--list` | 枚举设备后退出 |
| `--index` / `--serial` | 选择第 N 台 / 指定序列号的相机 |
| `--duration` | 采集时长，默认 60 s；正式测试建议 ≥180 s，长时稳定性才有意义 |
| `--pixel-format` | 设置像素格式，如 `Mono8`、`BayerRG8` |
| `--exposure` / `--gain` / `--fps` | 曝光(us) / 增益(dB) / 目标帧率 |
| `--quality-frames` | 用于坏点与 FFT 的图像帧数，默认 8（0 表示跳过图像质量项） |
| `--roi` | FFT 分析区域边长，默认 512 |
| `--image-quality` | 图像质量项是否计入接口判定：`diagnostic`（默认，只诊断）/ `enforce`（坏点率计入） |
| `--save-quality DIR` | 把质量帧 / 暗场帧保存为 PNG + index.csv（目视确认条纹/场景/过曝） |
| `--dark-field` | 主采集结束后追加暗场短采，用于暗场热像素 |
| `--dark-frames` | 暗场采集帧数，默认 4 |
| `--no-wait` | 暗场前不等待回车（自动化/无终端时） |
| `--mvs-path` | 手动指定 `MvImport` 目录 |
| `--simulate` / `--sim-profile` / `--sim-size` | 离线模拟（clean/jitter/drop/packet/deadpixel/banding） |
| `--out` | 报告输出目录，默认 `报告/` |

退出码：`0` 合格、`1` 警告、`2` 不合格、`3` 环境/相机错误、`4` 接口数据不完整（有计入项缺数据）。

## 4. 接口判定项与图像诊断（A 方案）

阈值集中在 `camera_test/thresholds.py`。接口综合判定只统计“计入”项；图像质量项默认只诊断，不改变接口结论：

| 指标 | 计入接口判定 | 合格 | 警告 | 不合格 | 实测口径 |
| --- | --- | --- | --- | --- | --- |
| 帧号丢帧率 | 是 | 0 | < 0.01% | ≥ 0.01% | `丢失帧数 / 理论帧数`，用相机帧号（nFrameNum）差值推算，自动处理 16/32 位回绕与设备重置 |
| 时间戳抖动比 | 是 | < 0.05 | 0.05 ~ 0.10 | > 0.10 | 相邻帧间隔的 `σ / 均值`，取本机单调时钟（微秒级）；同时打印设备时间戳的抖动比作对照 |
| 丢帧增长（30 s） | 是 | 0 | 1 ~ 5 | > 5 | 30 s 滑动窗口内新增丢帧数的最大值 |
| 丢包增长（30 s） | 是 | 0 | 1 ~ 10 | > 10 | 30 s 滑动窗口内新增丢包数的最大值，取自帧信息 `nLostPacket`（自动识别累计/单帧计数） |
| 坏点率 | 可选 | < 0.001 | 0.001 ~ 0.01 | > 0.01 | 平场图上与 3×3 邻域中值偏差 > `max(6σ, max(12%×邻域中值, 8 DN))` 且一半以上帧被标记的像素占比；默认诊断，`enforce` 时计入 |
| FFT 峰值比 | 否（诊断） | < 3 | 3 ~ 5 | > 5 | 中心 ROI 的 2D 频谱：最大幅值 / 中位数，再除以纯白噪声的理论极值 `√(2lnN)/1.177`（均匀噪声 ≈ 1）；只写“图像质量诊断” |

> 本工具当前已实现并计入的接口项是 B 组四项；A/C/F 的完整判定项见《评判标准_模版_v2.md》v2.1-A，尚未全部落到本工具。

### 4.1 口径说明（本次收紧的 6 处）

1. **抖动不看均值**：报告同时给出最长帧间隔、p99.9、卡顿次数（>2×中位间隔），
   偶发卡顿不会被平均值稀释；像素解码已移到独立线程，不再挤占采集周期。
2. **坏点用相对对比度**：`max(12%×邻域中值, 8 DN)` + `6σ`，换像素格式/位深/增益后口径一致。
3. **暗场单独测热像素**：`--dark-field` 盖镜头短采，热像素率取决于暗电流亮点，和平场坏点率互补。
4. **丢包与丢帧交叉校验**：丢包>0 但丢帧=0 时报告会注明“重传/统计口径，未造成掉帧”。
5. **丢包按采集会话统计**：每次运行独立计数，不跨会话累加。
6. **接口数据不完整不再判“合格”**：丢包字段缺失等导致计入项算不出来时，接口综合判定显示 **“不完整”**（退出码 4）。
   图像诊断缺图或非平场时只显示“图像质量诊断：不可用”，不改变接口结论。

> 时间戳抖动比用“标准差/均值”。若实验室口径是 `(max−min)/均值`，JSON 的 `stats.pp_ratio`
> 与逐帧 CSV 可直接复算。

### 4.2 图像输入有效性（坏点率 / FFT 的前置条件）

质量帧先经 `flat_field_check()` 判定，再决定坏点率/FFT 是否可用于诊断：

| 判定 | 判据 | 坏点率 | FFT 峰值比（诊断） |
| --- | --- | --- | --- |
| 平场 | 3×3 局部极差 p99 ≤ 8σ | 可用于诊断 | 可用于诊断 |
| 暗场（盖镜头） | ≤5 DN 像素 > 80% | 不可用（需要平场） | 可用于诊断 |
| 过曝 | ≥250 DN 像素 > 2% | 不可用 | 不可用 |
| 全局行/列条纹 | 均值谱峰比 > 10 且行（列）内一致性 > 20 | 不可用（条纹会污染坏点计数） | 可用于诊断（诊断组记不合格） |
| 场景结构 | 局部极差 p99 > 8σ 且非全局条纹 | 不可用 | 不可用 |

判定为“不可用”的项在报告里显示 `—`，图像质量诊断显示“不可用”，不改变接口判定；不会把非平场或过曝的图像误判成相机不合格。需要目视确认时加 `--save-quality 目录`，质量帧会存成 PNG 并附 `index.csv`（均值/最值/饱和比例）。

## 5. 补充检查（不参与接口判定）

| 检查项 | 判据 | 说明 |
| --- | --- | --- |
| 链路带宽 | 实测/需求 ≥0.95 通过；≥0.85 注意 | 3072×2048 Mono8@59.6 约需 375 MB/s；低于 100 MB/s 优先怀疑插了 USB2 口 |
| 帧完整性 | 异常帧 = 0 | 每帧字节数须等于 宽×高×位深，抓半帧/截断帧 |
| 帧率偏差 | ≤1% 通过；≤5% 注意 | 实测帧率 vs 目标（`--fps` 或相机上报） |
| 最长帧间隔 | ≤1.5× 通过；≤2.5× 注意 | 另给 p99.9 与卡顿次数（>2×中位） |
| 长时稳定性 | 分段丢帧率全 0 | 按 60 s 分段，看是否随时间恶化；不足两段时只作参考 |
| 进程资源 | RSS 增长 <200 MB | 采集期间内存与 CPU 占用（Linux 读 /proc，Windows 用 psapi） |
| 暗场热像素 | <0.0001 通过；<0.001 注意 | `--dark-field` 时才有；报告显示暗场中位、σ、最亮像素 |

这些阈值集中在 `camera_test/thresholds.py` 的 `Thresholds` 里（带“补充检查”注释），可按实验室口径调整。

## 8. 常见问题

**找不到 MVS SDK / 导入失败**
`MvImport` 目录里必须有 `MvCameraControl_class.py`。可用 `--mvs-path` 指定，
或在 Linux 下设置 `MVCAM_COMMON_RUNENV=/opt/MVS`。

**打开设备失败**
多半是 MVS 客户端正在占用相机，关掉预览再跑。

**报告显示“不完整”**
说明接口计入项里有指标没算出来（常见：SDK 不提供丢包字段）。按明细里的提示补齐数据后复测即可；
这不等于不合格，但不能当作合格交付。图像诊断缺图只会显示“图像质量诊断：不可用”，不影响接口结论。

**链路带宽不通过 / 低于需求**
3072×2048 Mono8@59.6 约 375 MB/s，接近 USB3 Gen1 实际上限：
换短屏蔽线、直插 NUC 后置 USB3 口、避免与其它 USB3 设备共用控制器；
也可用 `--fps 30 --pixel-format Mono8` 确认链路本身是否稳定。

**帧率偏差不通过**
检查 `AcquisitionFrameRate` 是否被曝光时间限制（曝光 ≥ 1/帧率 时必然掉帧），
或带宽不足导致实际帧率下降。

**时间戳抖动比偏大 / 有卡顿帧**
关闭 CPU 节能（performance governor）、避免虚拟机、不要在同一线程做图像处理
（采集与解码已分离）；NUC 上确认没有同时跑其它高占用任务。

**暗场热像素怎么测**
`--dark-field` 会提示盖住镜头，采集 4 帧（可调 `--dark-frames`）；
自动化场景加 `--no-wait`。盖不严会把环境光当成热像素。

**坏点率异常高**
确认是平场（盖镜头或均匀面光），并检查是否开了自动曝光/自动增益。

**报告显示“全局行/列条纹”或“每行一明一暗”**
先看 `质量帧/` 里的 PNG（需 `--save-quality`）：条纹贯穿全幅 → 多半是照明频闪（LED PWM、50/100 Hz）或读出异常；若只出现在某个物体上 → 是场景内容。盖住镜头复测，条纹消失即与被摄物无关。

**想把阈值改严**
直接改 `camera_test/thresholds.py` 的 `Thresholds`（接口项、诊断阈值与补充检查都在这里，
报告里的判据文字来自 `JUDGE_RULES` 与 `EXTRA_ADVICE`）。

## 9. 说明

* 参数文档里型号写作 `MV-CS606-10UC-PRO`，海康官方型号为 `MV-CS060-10UC-PRO`；
  两者指同一系列，本工具按 3072×2048 / USB3 Vision 处理，不影响采集逻辑。
* 颜色机型建议用 `--pixel-format Mono8`（或 `BayerRG8`，工具按灰度处理）以降低带宽。
* 采集线程与解码线程分离：采集循环只做“取帧 + 拷字节 + 记录元数据”，
  3072×2048 的转灰度在独立线程完成，避免污染时间戳抖动测量。
* FFT 峰值比只作诊断：先确认平场与光源无频闪；若峰值频率随光源变化，多为照明问题，
  若频率固定且暗场仍在，再查 FPN/读出。不要用单帧单 ROI 的峰值比直接判相机不合格。
